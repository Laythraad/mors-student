# التخزين (Storage Setup)

## أنواع البيانات المخزّنة

| النوع | المكان | ملاحظات |
| --- | --- | --- |
| قاعدة البيانات | `DATABASE_URL` (SQLite افتراضياً) | `docs/DATABASE.md` |
| ملفات الطالب المرفوعة | `UPLOAD_DIR` (افتراضي `uploads/` في جذر المشروع) | `docs/STORAGE.md` هذا |
| كتب المنهج (نص/صفحات) | داخل القاعدة (`book_pages`) | تُزرع للدِمو ويُرفع الأصل من الإدارة |
| فيديوهات | سجلات في القاعدة + روابط خارجية | الدِمو روابط `example.com` — الإدارة تضيف مصادرها |
| النسخ الاحتياطية | خارج شجرة المشروع | أدناه |

## الرفع: الأنواع والحجم

```env
UPLOAD_DIR=C:/path/to/mors.ai/uploads
MAX_UPLOAD_MB=25
ALLOWED_UPLOAD_TYPES=pdf,png,jpg,jpeg,webp,txt,md
```

- الفحص في `app/services/upload.py::validate` — الامتداد يجب أن يكون ضمن
  `ALLOWED_UPLOAD_TYPES`، الحجم > 0 و ≤ `MAX_UPLOAD_MB`.
- الامتداد وحده لا يكفي: الاسم يُنقّى (`_safe_filename`) ثم يُحفظ باسم
  **UUID** أصلي لا علاقة له باسم المستخدم — لا path traversal ممكن.

## تخطيط المجلدات

```text
UPLOAD_DIR/
  <student_id>/
    <uuid>.pdf
    <uuid>.png
    ...
```

- كل ملف تحت مجلد الطالب المالك → الحذف عبر §128 يحذف مجلد
  `uploads/<profile_id>` كاملاً.
- الأذونات الموصى بها (Linux): المالك = مستخدم الخدمة، `chmod 700` على
  `UPLOAD_DIR`؛ لا تضعه تحت `public/`.

## خط الفهرسة (Upload → Searchable)

كل مرحلة لها حالة مستقلة يراها الطالب («جاري الفهرسة» عوض رسالة فشل صامتة):

1. **save** — حفظ الملف (`status=received`).
2. **extract** — PDF عبر `pypdf`، نص/Markdown كما هو، صور عبر OCR
   (Tesseract أو `GEMINI_API_KEY`؛ إن غاب الاثنان يبقى الملف محفوظاً
   وتظهر الحالة بلا فقدان أصل).
3. **chunk + embed** — `app/rag/ingest.py` (حجم/تداخل `RAG_*` في
   `docs/AI_SETUP.md`).
4. **search** — `GET /api/media/search?q=` + استدعاء الكتاب في إجابات مورس.

المصادقة على كل استعلام: الملفات مرتبطة بـ`student_id` والوصول عبر
التوكن — رفع/قراءة ملفات طالب آخر مرفوض.

## صفحات الكتب (Reader)

- `seed_book_pages(db)` يمنح كل كتاب دِمو صفحات حقيقية لقارئ يعمل
  (فهرس، بحث، استشهاد `«<الكتاب> — صفحة N»`).
- الفحص **لكل كتاب** (وليس للقاعدة ككل): كتاب يُرفع لاحقاً من الإدارة
  يحصل على صفحات عند أول إقلاع بعد رفعه.

## النسخ الاحتياطي

```powershell
# أوقف الخادم (أو استخدم نسخاً ذرياً) ثم (من جذر المشروع):
Copy-Item mors.db backup\mors.db
Copy-Item -Recurse uploads backup\uploads
```

- احتفظ بقاعدة + `UPLOAD_DIR` **معاً** في نفس اللقطة الزمني، وإلا ستتأثر
  سجلات الرفع (المفاتيح داخل القاعدة تشير لملفات).
- اختبر الاستعادة في بيئة مؤقتة: انسخ الملفين، شغّل الخادم، افتح
  `/media` وتحقق من قائمة الرفعات.

## توسعة التخزين

- تغيير `UPLOAD_DIR` إلى قرص أكبر: عدّل `.env` **ونقل المجلد** (المسارات
  داخل القاعدة نسبية إلى التخطيط `<dir>/<student_id>/<uuid>` — عند التحويل
  نسخ الملفات كما هي يكفي ما دام البنية نفسها).
- تخزين سحابي (S3-style) يتطلب Adapter جديداً في `services/upload.py` —
  خارج نطاق الإصدار الحالي.
